# 入境游客服务接力

按「一次旅次」把入境游客从境外签证咨询、落地移动支付到景区换乘与接待串成一条服务接力：游客的语言偏好和无障碍需求只讲一次，每个服务方只收到完成当前环节所需的最小资料，行业管理人员只能看到匿名堵点聚合。

## 目录结构

- `src/catalog.js` — 环节、服务方、资料分组与最小必要矩阵（目录事实，无个人信息）
- `src/relay.js` — 接力引擎：明确授权、交接包投影、五类收窄事件、撤回与 TTL 失效、游客接力卡
- `src/analytics.js` — 匿名堵点统计：无身份入口、k-匿名小群抑制、只出通关/支付/接待三类聚合
- `contracts/domain.schema.json` — 领域资料契约
- `contracts/handoff.schema.json` — 交接包契约
- `fixtures/domain.json` — 不含真实个人信息的领域示例
- `scripts/demo.js` — 端到端演示（`node scripts/demo.js`）
- `test/` — `node --test` 测试

## 产品规则如何落地

**一次采集，全程接力。** 旅次建立时生成匿名接力编号和临时联络码（`ch-…`，不是手机号或邮箱）。语言、无障碍、餐饮等行程需求只在首个环节采集一次，系统不设第二次填表。

**明确同意是共享闸门。** `grantConsent` 要求 `explicit: true` 且逐组勾选；没有效授权的分组在投影阶段直接剔除并在交接包 `dropped` 中注明。每次交接包都带 `consent_id`。

**最小必要投影。** 每个环节只拿到目录矩阵列出的分组（如境外咨询只有行程需求；支付环节是行程需求+支付帮助+临时联络码；换乘环节才出现核验结果）。入库按字段白名单过滤，`passport_number`、`phone` 等身份字段在写入时即丢弃；证件原件与证件号从不进入交接包。

**交接内容随事件收窄：**

| 事件 | 行为 |
| --- | --- |
| 行程变动 | 未交付的旧包作废（`superseded/itinerary_changed`），重发包按新行程裁剪 |
| 同行人拆分 | 座位与人数立即下调，沿用旧人数的未交付包作废 |
| 服务方替换 | 未交给旧方的包撤回（`revoked/provider_replaced`），新包指向新服务方；已交付资料只保留到 TTL |
| 付款失败 | 支付帮助只剩 `help_status/retry_required`，下一联系人回到支付服务方，重试成功后恢复 |
| 证件过期 | 下游交接一律移除核验结果，接力卡把下一联系人指向重新核验 |

**撤回与到期。** 可整单或按组撤回，所有尚未交付的交接包立即变为 `revoked`，停止尚未发生的共享；已交付资料按分组 TTL 到期抹除（支付帮助 7 天、交通与接待 2 天、核验结果 30 天；行程需求与临时联络码随撤回停用、随旅次关闭抹除）。`sweep()` 按 TTL 抹除并按 `valid_until` 自动识别证件过期。

**游客随时知情。** `relayCard` 给出当前环节、下一联系人（含临时联络码）、待办动作、提醒，以及已共享/待共享清单（交给谁、哪些分组、何时到期）。

**行业管理视角不可追溯个人。** 统计入口只接受 `domain/stage_id/code/bucket`，出现旅次编号、证件、联络码等字段一律拒收；信号到达即并入按天计数，不留明细；同一时间桶不足 k（默认 5）的小群只显示被抑制总量，无法借小群反推个人旅程。

## 本地运行

```bash
npm test        # 21 项测试：授权闸门、最小必要、五种收窄、撤回、TTL、k-匿名
node scripts/demo.js
```

仓库不保存账号、密钥、连接串或真实身份信息。
