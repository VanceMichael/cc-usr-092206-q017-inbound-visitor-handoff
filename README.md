# 入境游客服务接力

衔接入境游客从行前咨询到抵达游览和求助的多方服务：按一次旅次建立服务接力，游客明确同意后，各环节服务商只收到完成当前环节所需的资料。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括入境游客、旅行服务商、支付与交通服务方、文旅行业管理人员。

资料所依据的领域事实如下：

- 入境旅游便利化讨论市场营销、数字创新和跨境支付
- 参与者来自政府、行业协会、金融机构和文旅企业
- 行业希望推动服务标准化、数字化和国际化

## 产品模块

- `src/relay.js` — 旅次接力核心：旅次创建、明确同意与撤回、交接调度、行程变动 / 同行人拆分 / 服务方替换 / 付款失败 / 证件过期等事件处理、敏感资料到期清理、游客视图（下一联系人与待办动作）。
- `src/packets.js` — 交接包：环节（通关、支付、交通、接待）与五类可交接资料（行程需求、旅行文件核验结果、支付帮助、交通安排、接待确认）的最小必要映射、面向服务商的假名引用、交接包存续期。
- `src/analytics.js` — 匿名统计：行业管理人员只能写入并读取聚合维度（日期、环节、堵点类型），低于最小单元阈值的计数被抑制，任何可识别个人的维度会被拒绝。

## 隐私与授权约定

- 任何共享都发生在游客明确同意之后；撤回授权立即停止尚未发生的共享。
- 每个服务商只收到当前环节所需的类别；旅行文件只交接核验结论，不交接证件本身。
- 行程变动、同行人拆分、服务方替换、付款失败、证件过期都会让交接内容随之收窄，已送达的服务商收到丢弃过时字段的通知。
- 核验结论与交接包都有存续期，到期即失效。
- 游客随时可查看下一联系人、待办动作和即将共享的内容。

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实和约束。运行 `npm test` 即可检查领域资料与接力产品的全部行为。仓库不保存账号、密钥、连接串或真实身份信息。
